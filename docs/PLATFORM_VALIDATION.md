# Platform Validation & Feasibility Specification: PRIVEX

## 1. Overview

This document provides a rigorous, platform-by-platform engineering validation for every capability within the PRIVEX ecosystem. Each subsystem is assessed across six foundational questions:
1. **WHERE** does it run?
2. **WHY** does it run there?
3. **WHAT** data does it require?
4. **CAN** it work offline?
5. **DOES** it require privileged permissions?
6. **WHAT HAPPENS** if the host platform restricts or revokes intended permissions?

---

## 2. Platform Evaluations

### 2.1 Mobile Application (Android / iOS)

#### Feature: SMS & Inbound Message Security
- **WHERE**: Client device (Android Background Notification Listener; iOS `IdentityLookup` SMS Message Filter Extension).
- **WHY**: Inbound phishing and scam messages directly target mobile communications (SMS, WhatsApp, Telegram notifications).
- **WHAT Data Required**: Inbound sender identifier, message body string, attached URLs/numbers.
- **CAN it Work Offline**: **YES**. All NLP intent analysis, regex rules, and Bloom filter lookups run locally.
- **Privileged Permissions**:
  - Android: `BIND_NOTIFICATION_LISTENER_SERVICE` or Default SMS handler entitlement.
  - iOS: User enablement of the app in *Settings -> Messages -> Unknown & Spam*.
- **Graceful Degradation If Restricted**:
  - If notification/SMS permission is denied, ambient background scanning is disabled.
  - The application cleanly degrades to **On-Demand Clipboard & Share Target Mode**: users copy or share any suspicious text into the app or via the system Share Sheet for instant local evaluation.

#### Feature: QR Code & Visual Phishing Scanner
- **WHERE**: Mobile device camera viewfinder and image analysis pipeline.
- **WHY**: QR code phishing ("quishing") and malicious screen captures occur predominantly on camera-equipped mobile devices.
- **WHAT Data Required**: Camera image frames or user-selected screenshot bitmaps.
- **CAN it Work Offline**: **YES**. QR decoding and logo OCR/matching execute entirely on-device via NPU/GPU acceleration.
- **Privileged Permissions**: `CAMERA` (for live QR scanning), `READ_MEDIA_IMAGES` (for gallery screenshot import).
- **Graceful Degradation If Restricted**:
  - If camera access is denied, live viewfinder scanning is unavailable; user can still paste raw decoded URLs manually into the scan bar.

#### Feature: Mobile AI Security Assistant
- **WHERE**: On-device Small Language Model (Gemma 2B INT4 / Llama-3.2 1B via CoreML/TFLite).
- **WHY**: Users require immediate, interactive conversational explanations of threats directly on their primary mobile device.
- **WHAT Data Required**: Structured `EvidenceChain` generated by local analyzers.
- **CAN it Work Offline**: **YES**. The SLM weights are bundled or downloaded once locally.
- **Privileged Permissions**: None beyond standard app execution storage for weights.
- **Graceful Degradation If Restricted**:
  - If device memory is constrained (<3GB RAM) or model download is deferred, system seamlessly falls back to the deterministic, template-based Explanation Engine with zero loss of threat detection accuracy.

### 2.2 Desktop Security Software (Windows / macOS)

#### Feature: Local File & Download Inspection
- **WHERE**: Local OS background service (Windows Service / macOS launchd daemon) integrated with Tauri/Rust UI.
- **WHY**: Desktop environments are the primary vector for malicious executable downloads (`.exe`, `.msi`, `.dmg`, `.pkg`, `.zip`, `.js`).
- **WHAT Data Required**: File path, file size, SHA-256 header hash, PE/Mach-O header bytes, entropy sample.
- **CAN it Work Offline**: **YES**. Uses local Yara rules, file format structure heuristics, and cached malware hashes.
- **Privileged Permissions**: File system directory read access on user Downloads and temporary folder directories.
- **Graceful Degradation If Restricted**:
  - If background filesystem hooks are not permitted, the desktop app falls back to **Drag-and-Drop / File Picker Scan Mode**, scanning files explicitly supplied by the user.

#### Feature: Desktop Messaging & Clipboard Protection
- **WHERE**: Unprivileged Desktop user session.
- **WHY**: Users frequently receive phishing links in desktop enterprise chat apps (Slack, Teams, Discord, Outlook).
- **WHAT Data Required**: Clipboard text changes (opt-in) or user-submitted text.
- **CAN it Work Offline**: **YES**.
- **Privileged Permissions**: Clipboard read access (Windows standard; macOS Accessibility/Input Monitoring if ambient).
- **Graceful Degradation If Restricted**:
  - If clipboard monitoring is disabled by the user or OS policy, the app operates strictly via hotkey-activated or manual scan input.

### 2.3 Browser Extension (Chrome, Edge, Firefox)

#### Feature: Real-Time Pre-Navigation URL Inspection
- **WHERE**: Browser Extension Service Worker (Manifest V3) running compiled WASM detection core.
- **WHY**: Intercepting malicious links *before* navigation prevents drive-by exploitation, credential theft, and session hijacking.
- **WHAT Data Required**: Navigation target URL, domain hostname, URL parameters.
- **CAN it Work Offline**: **YES**. The WASM engine and Bloom filter lookups operate entirely within the browser sandbox with zero network requests.
- **Privileged Permissions**: `webNavigation`, `declarativeNetRequest`, or `webRequest` / `activeTab`.
- **Graceful Degradation If Restricted**:
  - If broad host permissions are refused by the user, the extension uses `activeTab` to inspect pages only when the extension icon is clicked or navigation occurs from an active tab context.

#### Feature: In-Page DOM & Phishing Input Warning
- **WHERE**: Isolated Content Script injected into web pages.
- **WHY**: Phishing sites often inject deceptive login overlays, form action redirection, or spoofed brand assets inside dynamic client DOMs.
- **WHAT Data Required**: Form action target URLs, input types (`password`, `credit-card`), page title, document domain.
- **CAN it Work Offline**: **YES**. DOM structure analysis is performed locally in browser memory.
- **Privileged Permissions**: Content script injection on visited pages.
- **Graceful Degradation If Restricted**:
  - If content scripts cannot be injected (e.g. Chrome Web Store restricted URLs, internal `chrome://` pages), browser-level warnings are suspended for that origin without crashing.

### 2.4 Web Application Dashboard (Next.js / Cloud-Assisted Portal)

#### Feature: Manual Deep-Scan & Threat Analysis
- **WHERE**: Web Browser Client with optional backend heavy-analysis sandbox.
- **WHY**: Provides a zero-install portal for users on unsupported platforms (Linux, ChromeOS, guest workstations) to evaluate suspicious links and text snippets.
- **WHAT Data Required**: Manually pasted URL or text snippet.
- **CAN it Work Offline**: **NO** (Web Dashboard relies on web hosting; however, client-side WASM engine executes scans locally in browser RAM once page assets are loaded).
- **Privileged Permissions**: None (standard web application).
- **Graceful Degradation If Restricted**:
  - If user is offline, a Service Worker serves a cached Progressive Web App (PWA) shell with client-side WASM scanning.

---

### 2.5 Shared Detection Engine (`packages/core`)

#### Feature: Multi-Modal Analysis & Risk Scoring
- **WHERE**: Embedded in all client hosts (compiled to native Rust/C libraries for Mobile/Desktop and WebAssembly for Browser/Web).
- **WHY**: Guarantees 100% detection parity, eliminate duplicated logic, and enforces local-first privacy.
- **WHAT Data Required**: Normalized input string or buffer and specified `InputType`.
- **CAN it Work Offline**: **YES** (100% self-contained).
- **Privileged Permissions**: Zero OS privileges required; pure computational library.
- **Graceful Degradation If Restricted**:
  - Fully immune to OS privilege restrictions.

---

### 2.6 Optional Backend Services

#### Feature: Threat Feed Aggregation & Delta OTA Distribution
- **WHERE**: Cloud infrastructure (stateless container cluster + global CDN).
- **WHY**: Compiles millions of global threat intelligence indicators from authoritative sources (PhishTank, OpenPhish, etc.) into compact, client-consumable Bloom filters (<5MB).
- **WHAT Data Required**: Public threat feeds, domain reputation feeds. **ZERO USER DATA**.
- **CAN it Work Offline**: Clients function completely without backend availability using cached datasets.
- **Privileged Permissions**: Standard cloud server execution.
- **Graceful Degradation If Restricted**:
  - If backend is offline, clients continue uninterrupted using local heuristics, cached Bloom filters, and ML models.

## 3. Platform Capability vs. Constraint Matrix

| Platform | Primary Mode | Ambient Monitoring | Ingestion Method | Fallback Mode on Permission Revocation |
|---|---|---|---|---|
| **Android** | Foreground/Background | Notifications (`NotificationListener`) | Push Notification capture, SMS Intent | Manual Share Sheet & Quick Settings tile |
| **iOS** | Sandboxed Extensions | SMS (`IdentityLookup`), Safari Ext | Isolated OS Extension filters | Share Sheet, Clipboard, Manual URL paste |
| **Windows** | Desktop Daemon | File Downloads (`ReadDirectoryChangesW`) | File watcher, System tray hook | Drag-and-drop file/text scanner |
| **macOS** | Desktop Daemon | File Downloads (`FSEvents`) | File watcher, Menu bar hook | Drag-and-drop file/text scanner |
| **Chrome/Edge** | Manifest V3 Ext | Tab navigation (`webNavigation`) | Service Worker interceptor | On-click `activeTab` inspection |
| **Firefox** | Manifest V3 / WebExt | Tab navigation (`webRequest`) | WebExtension background script | On-click inspection |
| **Web Portal** | Browser Tab | None (Manual only) | Web form input | Client-side PWA cached execution |
