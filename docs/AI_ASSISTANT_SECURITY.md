## 2. SECURITY DECISION AUTHORITY: CORE > AI

> **CONSTITUTIONAL INVARIANT**: `CORE SECURITY ENGINE > AI ASSISTANT`

1. **Zero Override Authority**: The AI model has zero capability to alter, downgrade, elevate, or question the risk score ($0-100$), verdict (`ALLOW`, `INFORM`, `CAUTION`, `SUSPICIOUS`, `DANGEROUS`), or recommended action.
2. **Authority Isolation Gate**: If an output generated by any local model contains phrases attempting to declare a `CAUTION`, `SUSPICIOUS`, or `DANGEROUS` target as safe (e.g., "this is safe", "no threat detected", "verified legitimate"), `SchemaValidator` rejects the output with an `AuthorityViolationError` and falls back immediately to `TemplateFallbackEngine`.
3. **Deterministic Precedence**: The final user action recommendation is mapped deterministically from the core risk score, never synthesized by the language model.

## 3. DANGEROUS REQUEST BOUNDARY (RESPONSE POLICY)

The AI assistant refuses to assist with:
- Bypassing, disabling, or turning off antivirus, phishing filters, or platform protection.
- Crafting phishing messages, spoofed domains, or credential harvesting kits.
- Developing malware, ransomware, exploits, or obfuscated payloads.
- Stealing or exfiltrating user credentials, tokens, or private keys.

Evaluated deterministically in `ResponsePolicy.evaluateUserIntent()` in $< 0.01\text{ ms}$.

---

## 4. STRICT OUTPUT SCHEMA SPECIFICATION

Outputs must strictly adhere to the `AssistantOutput` interface:
- `headline`: string, $1 \le \text{length} \le 60$ characters.
- `summaryParagraph`: string, $1 \le \text{length} \le 300$ characters.
- `dangerFactors`: array of $1 \text{ to } 4$ strings, each $\le 100$ characters.
- `recommendedSteps`: array of $1 \text{ to } 3$ strings, each $\le 120$ characters.
- `uncertaintyNote`: string, $\le 150$ characters.
- `inferenceStatus`: enum `'LOCAL_MODEL' | 'DETERMINISTIC_FALLBACK' | 'SANITIZED'`.
- `executionTimeMs`: non-negative number.

Any schema mismatch instantly triggers `TemplateFallbackEngine.generateFallback()`.
